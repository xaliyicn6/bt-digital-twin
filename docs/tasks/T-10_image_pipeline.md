# T-10 影像上传与预处理

| 项 | 内容 |
| --- | --- |
| 阶段 | P3 |
| 依赖前置 | T-06 |
| 产出 | 影像预签名上传、EXIF/POS 解析、缩略图、位姿缺失检测、image_file 落库 |
| 验收门 | 位姿缺失被标记；缩略图生成成功；GSD 计算正确 |
| 预估工作量 | 4 人日 / 3 卡 |
| 人工主导 | 否 |
| 外部阻塞 | 阻塞于 C-04（是否有竣工测量与控制点，影响位姿来源） |

## 1. 目标

让影像带着可追溯的位姿信息入库，为后续切片与配准提供输入。

## 2. 输入

- API-09
- image_file（pose、gsd、intrinsics）
- 异步任务框架 T-11

## 3. 改动范围

- 允许：backend/app/modules/media/image/**、backend/app/workers/image_worker.py
- 禁止：在同步请求内做解码与转码

超出上述范围即视为越权改动，即使代码正确也退回。

## 4. 实现要点

- 位姿来源三种：EXIF GPS / 外部 POS 文件 / 现场标靶；三种都要落 `pose_source`
- GSD 由像素尺寸与拍摄距离计算，单位 mm/px，保留 2 位；无距离时置空不得瞎算
- 人脸与车牌在缩略图阶段即打码（隐私优先），原图保留
- 单张 > 50 MB 的影像必须走分片

## 5. DoD（可验证的完成定义）

- 无位姿影像入库后 `pose_status=MISSING` 且不参与推理
- 缩略图长边 1920、质量 80
- GSD 字段为空时前端显示“待确认”
- 批量上传 200 张不阻塞其他请求

## 6. 验收用例

| # | 输入 | 操作 | 期望结果 |
| --- | --- | --- | --- |
| 1 | 上传无 EXIF 的 JPEG | POST /images/init | 入库 pose_status=MISSING，提示补 POS 或标靶 |
| 2 | 上传 8000×6000 影像 | 上传 | 自动分片，complete 后生成缩略图 |
| 3 | 缩略图含清晰人脸 | 生成缩略图 | 人脸区域已模糊，原图不受影响 |

## 7. 依赖与顺序

T-06 与 T-11 之后；T-20（推理）依赖它。

## 8. 常见坑

- 不要用度坐标算 GSD
- 不要在前端压缩后当原图入库
- 不要相信 EXIF 的坐标系标注
