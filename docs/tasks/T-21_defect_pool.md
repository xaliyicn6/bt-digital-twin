# T-21 候选缺陷池与人工确认

| 项 | 内容 |
| --- | --- |
| 阶段 | P6 |
| 依赖前置 | T-20 |
| 产出 | API-12/13、候选列表、确认/驳回、落 defect_ledger、误报样本回流 |
| 验收门 | 确认后生成台账；驳回可回训；重复确认幂等 |
| 预估工作量 | 5 人日 / 3 卡 |
| 人工主导 | 是（人工主导：缺陷分级与误报判定） |
| 外部阻塞 | 阻塞于 C-11（精确率与测试集）、C-03（分级） |

## 1. 目标

把 AI 输出变成“有人签字”的台账，AI 永不直接写正式缺陷。

## 2. 输入

- API-12、API-13
- defect_candidate / defect_ledger / defect_review

## 3. 改动范围

- 允许：backend/app/modules/defect/**、frontend/src/views/defect/**
- 禁止：任何路径让 AI 直接写 defect_ledger

超出上述范围即视为越权改动，即使代码正确也退回。

## 4. 实现要点

- 确认动作必须记录操作人、时间、修改后的等级与位置
- 驳回必填原因（误报/重复/位置偏移），写 defect_review 供回流
- 同一候选重复确认返回首次结果（幂等）
- 确认后缺陷状态 CONFIRMED 才允许建单

## 5. DoD（可验证的完成定义）

- 确认 1 条候选生成 1 条台账且可查
- 重复确认不产生第二条
- 驳回样本可导出为训练集格式
- 候选列表按置信度与状态过滤

## 6. 验收用例

| # | 输入 | 操作 | 期望结果 |
| --- | --- | --- | --- |
| 1 | 确认候选并上调等级 | POST /defects/candidates/{id}/confirm | 台账生成，level 为修改后值，审计有记录 |
| 2 | 对同一候选重复确认 | 再次 POST | 返回首次结果 200，不新增台账 |
| 3 | 驳回但不填原因 | POST | 422，detail=reason 必填 |

## 7. 依赖与顺序

T-20 之后；T-08 建单依赖台账状态。

## 8. 常见坑

- 不要允许批量确认无人工痕迹
- 不要把候选池当台账查询
- 不要丢了驳回原因，那是回训唯一素材
