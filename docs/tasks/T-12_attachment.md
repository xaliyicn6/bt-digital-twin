# T-12 附件与现场回传

| 项 | 内容 |
| --- | --- |
| 阶段 | P3 |
| 依赖前置 | T-08 |
| 产出 | attachment 关联、照片压缩与后台续传、禁止类型拦截、容量与数量校验 |
| 验收门 | 弱网续传成功；类型拦截生效；附件与工单/缺陷双向可查 |
| 预估工作量 | 3 人日 / 2 卡 |
| 人工主导 | 否 |
| 外部阻塞 | 无 |

## 1. 目标

让外业在没有稳定网络时也能把处置照片可靠传回，且不丢、不重、不错挂。

## 2. 输入

- attachment / file_object_link
- API-19
- 工单 SUBMIT_REPAIR 守卫

## 3. 改动范围

- 允许：backend/app/modules/file/**、frontend/src/views/mobile/**
- 禁止：绕过预签名直传

超出上述范围即视为越权改动，即使代码正确也退回。

## 4. 实现要点

- 允许类型白名单：jpg/png/pdf/mp4；魔数校验，不只看扩展名
- 手机端长边 1920、质量 80 压缩后上传，原图可另行上传
- 上传队列用 Outbox 持久化，App 重启后续传
- 同一工单照片上限 20 张，超限 422

## 5. DoD（可验证的完成定义）

- 断网拍照 5 张，恢复后自动续传且无重复
- 上传 .php 返回 422 + BT-80001
- 附件列表按 object_type/object_id 正确过滤
- 压缩后单张 < 800 KB（1920 长边）

## 6. 验收用例

| # | 输入 | 操作 | 期望结果 |
| --- | --- | --- | --- |
| 1 | 飞行模式拍 3 张后恢复网络 | 切网 | 3 张依次续传，服务端计数 3 不重复 |
| 2 | 上传伪装成 jpg 的 php | 上传 | 422，code=BT-80001 |
| 3 | 同一工单传第 21 张 | 上传 | 422，detail=附件数量超限 |

## 7. 依赖与顺序

T-08 之后。T-13 的通知会引用附件状态。

## 8. 常见坑

- 不要用扩展名判断类型
- 不要在 App 内存里排队上传，重启即丢
- 不要重复写 file_object_link
