# T-08 工单流转与验收接口

| 项 | 内容 |
| --- | --- |
| 阶段 | P2 |
| 依赖前置 | T-07 |
| 产出 | API-16/17/18：建单、流转、验收；待办列表；重复建单拦截；合并单 |
| 验收门 | 三接口契约通过；重复建单 409；验收退回可回到 IN_PROGRESS |
| 预估工作量 | 5 人日 / 3 卡 |
| 人工主导 | 否 |
| 外部阻塞 | 阻塞于 C-12（SLA 时限） |

## 1. 目标

让养护人员从缺陷确认到闭环全程在系统内完成，且每一步都有事件留痕。

## 2. 输入

- API-16 至 API-18
- defect_ledger 的 CONFIRMED 缺陷
- attachment 表

## 3. 改动范围

- 允许：backend/app/modules/workorder/api/**、frontend/src/views/workorder/**
- 禁止：绕过引擎直接改 status

超出上述范围即视为越权改动，即使代码正确也退回。

## 4. 实现要点

- 建单必须校验缺陷状态为 CONFIRMED 且无未结单，重复返回 409 + BT-70002
- 验收通过前校验附件齐全（现场照片 ≥2 张且含处置说明）
- 退回时必须写原因，SLA 顺延退回耗时
- 所有写接口必须带 `Idempotency-Key`，缺失返回 400

## 5. DoD（可验证的完成定义）

- API-16/17/18 契约测试通过
- 重复建单被部分唯一索引拦截
- 验收退回后状态回 IN_PROGRESS 且事件链完整
- 待办列表按数据范围过滤

## 6. 验收用例

| # | 输入 | 操作 | 期望结果 |
| --- | --- | --- | --- |
| 1 | 对同一缺陷二次建单 | POST /workorders | 409，code=BT-70002 |
| 2 | 现场照片仅 1 张即提交验收 | POST /workorders/{id}/acceptance | 422，detail 指出照片数量不足 |
| 3 | 验收人退回并填原因 | POST .../acceptance | 状态回 IN_PROGRESS，事件记录原因与操作人 |

## 7. 依赖与顺序

T-07 之后；T-12、T-13 依赖它的事件流。

## 8. 常见坑

- 不要让前端传 status，只传 event
- 不要忽略软删除的工单仍占用唯一索引
- 不要用 0-4 数字代替状态码
