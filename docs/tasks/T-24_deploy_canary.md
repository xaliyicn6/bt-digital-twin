# T-24 部署与灰度

| 项 | 内容 |
| --- | --- |
| 阶段 | P6 |
| 依赖前置 | T-02,T-16 |
| 产出 | 容器编排、内网分区、迁移脚本管理、灰度 10/50/100、回滚手册 |
| 验收门 | 一键部署；迁移可前向可回滚；灰度 24h 观察有记录 |
| 预估工作量 | 5 人日 / 3 卡 |
| 人工主导 | 是（人工主导：发布窗口与网络分区需业主确认） |
| 外部阻塞 | 阻塞于 C-14（等保等级）、C-16（RPO/RTO）、C-19（灰度窗口） |

## 1. 目标

让上线可重复、可回滚、可观测，不靠人肉记忆。

## 2. 输入

- docker-compose / k8s 清单
- db/migrations/**
- T-16 指标

## 3. 改动范围

- 允许：deploy/**、db/migrations/**、Makefile
- 禁止：手工在生产库执行 DDL

超出上述范围即视为越权改动，即使代码正确也退回。

## 4. 实现要点

- 镜像 tag 用 git sha，禁 latest；迁移脚本前向只增不改
- 灰度按用户比例 10%→50%→100%，每级 ≥24h（H-07）
- 回滚只回应用镜像，不回数据库（迁移必须向后兼容一个版本）
- 内网分区：应用区、数据区、推理区各自独立网络策略

## 5. DoD（可验证的完成定义）

- 空环境 `make deploy` 成功
- 迁移在含数据的环境执行成功且可回滚应用版本
- 灰度一级切换有记录
- 回滚演练在 30 分钟内完成

## 6. 验收用例

| # | 输入 | 操作 | 期望结果 |
| --- | --- | --- | --- |
| 1 | 新版本迁移新增非空列 | 部署 | 先加可空列→回填→再加约束，三步脚本齐全 |
| 2 | 灰度 10% 时错误率超阈 | 观察 | 自动停止放量并触发 P1 告警 |
| 3 | 回滚到上一镜像 | 执行 | 旧版本兼容新 schema，业务无报错 |

## 7. 依赖与顺序

最后一张卡，依赖前 23 张的产物。

## 8. 常见坑

- 不要用 latest 镜像
- 不要在生产手敲 SQL
- 不要让回滚依赖反向迁移脚本
