# T-04 RBAC 与数据分级

| 项 | 内容 |
| --- | --- |
| 阶段 | P1 |
| 依赖前置 | T-03 |
| 产出 | 权限点校验依赖、数据范围过滤、四级密级控制、导出审批钩子 |
| 验收门 | 5 角色 × 资源 × 操作矩阵可验证；越权返回 403 + BT-20004 |

| 外部阻塞 | 阻塞于 C-13（数据密级与测绘成果口径） |

## 1. 目标

把“谁能看哪座桥的哪些数据”变成可执行过滤器，而不是散落在各接口里的 if。

## 2. 输入

- V1.2 第 13 章 角色矩阵与数据分级
- sys_role / sys_permission / sys_role_permission / sys_role_data_scope

## 3. 改动范围

- 允许：backend/app/modules/rbac/**、shared/scope.py
- 禁止：在业务模块内自写 SQL 过滤条件

超出上述范围即视为越权改动，即使代码正确也退回。

## 4. 实现要点

- 权限点命名 `模块:操作`，如 `asset:read`、`order:transition`，与契约 security 段一致
- 数据范围四档 PROJECT/BRIDGE/TUNNEL/SECTION，由 `sys_role_data_scope` 驱动，越界返回 403 而非 404（避免探测）
- 密级 4 级：公开/内部/敏感/涉密；敏感级导出需审批单号，涉密级禁止导出
- 权限变更必须写审计日志并撤销该用户全部 access 的 jti

## 5. DoD（可验证的完成定义）

- 5×N 矩阵逐条有用例
- 越权访问返回 403 + BT-20004
- 导出接口在无审批单号时返回 422
- 权限变更后 1 秒内旧 token 失效

## 6. 验收用例

| # | 输入 | 操作 | 期望结果 |
| --- | --- | --- | --- |
| 1 | 巡检员查非本人数据范围的桥 | GET /bridges/{id} | 403，code=BT-20004 |
| 2 | 只读访客调 POST /workorders | 创建工单 | 403，code=BT-20003 |
| 3 | 敏感级点云导出未填审批单号 | POST /exports | 422，detail 指向 approval_no 缺失 |

## 7. 依赖与顺序

T-03 之后。所有业务卡依赖它取当前用户与数据范围。

## 8. 常见坑

- 不要用前端隐藏按钮代替后端校验
- 不要把 403 写成 404 图省事，契约已区分
- 密级判断不得硬编码，走 dict_type
