# T-20 AI 推理服务封装

| 项 | 内容 |
| --- | --- |
| 阶段 | P6 |
| 依赖前置 | T-10 |
| 产出 | 推理客户端、切片与批处理、置信度阈值、结果落 defect_candidate、模型版本登记 |
| 验收门 | 单张 ≤2 s（GPU 条件）；失败可重试；版本可追溯 |
| 预估工作量 | 6 人日 / 4 卡 |
| 人工主导 | 是（人工主导：模型选型与阈值） |
| 外部阻塞 | 阻塞于 C-08（GPU 配置）、C-11（精确率目标） |

## 1. 目标

把推理封装成受控服务调用，业务侧只关心任务与结果，不关心模型细节。

## 2. 输入

- API-10、API-11
- model_registry
- defect_candidate

## 3. 改动范围

- 允许：backend/app/modules/inference/**、workers/inference_worker.py
- 禁止：在业务容器内加载模型权重

超出上述范围即视为越权改动，即使代码正确也退回。

## 4. 实现要点

- 4000×3000 影像必须切片（640 输入下 20–60 块），切片重叠 20%
- 结果写候选池而非台账，`confidence` 与 `model_version` 必填
- 推理服务 503 时按降级矩阵转人工，不阻断上传
- 所有调用记录 `image_id`、切片坐标、耗时，便于复现

## 5. DoD（可验证的完成定义）

- 同一影像重复提交结果一致（同版本）
- 推理服务不可用返回 503 + BT-90003 且任务置 FAILED
- 候选结果含 bbox 与置信度，阈值以下不入池
- 模型版本可反查

## 6. 验收用例

| # | 输入 | 操作 | 期望结果 |
| --- | --- | --- | --- |
| 1 | 提交 20 张影像 | POST /inference/tasks | 每张生成子任务，状态可查，结果落候选池 |
| 2 | 推理容器停止 | 提交任务 | 503 + BT-90003，工单流程不受影响 |
| 3 | 置信度 0.31 低于阈值 0.4 | 推理完成 | 不入候选池，记录被过滤原因 |

## 7. 依赖与顺序

T-10、T-11 之后；T-21 依赖候选池数据。

## 8. 常见坑

- 不要把推理与业务同进程
- 不要在切片边缘重复计数（需 NMS 合并）
- 不要用 CPU 跑 4000×3000 后声称满足 200 ms
