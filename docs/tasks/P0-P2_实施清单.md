## 2. 确认门（C1–C8）与裁决结论

| 门 | 问题 | 裁决 |
|---|---|---|
| C1 | `tech_grade`(1-5) 与 `defect_level`(L1/L2/L3) 冲突 | **两个都要，互不冲突**：L1–L3 是缺陷严重度；1–5 类是构件技术状况等级。Alembic 0005 给 `component` 加 `tech_grade`（默认 NULL，范围 1–5）；资产树圆点/徽标一律读 `tech_grade`；**不改 `db/schema.sql` 既有表定义** |
| C2 | 垂直度阈值是否为规范给定 | 阈值外置到 `backend/config/verticality_thresholds.yaml`：`<2‰→1类`、`2–3‰→2类`、`3–4‰→3类`、`4–5‰→4类`、`>5‰→5类`。支持 `VERTICALITY_THRESHOLD_CONFIG` 覆盖路径，按 mtime 热加载；`>4‰ 判 4/5 类` 的准值未给，按 4–5/5+ 实现，并在配置与文档标注"工程解释，可被甲方规范覆盖" |
| C3 | 条款号无法核验 | 统一写 `JTG/T H21-2011 第 5.x 条（具体条款以正式规范为准）`，不编造具体条款号 |
| C4 | 新增 `/reports/{task_id}/export` 属契约变更 | **追认保留**；本轮新增 `POST` 以承载前端截图，`GET` 保留兼容无截图场景 |
| C5 | 推理服务缺失 | YOLO 继续 Mock，界面保留"未调用 YOLO"显式标注 |
| C6 | 全桥评分无出处 | 先用示例 82.5 分；JSON 增加 `score_detail`，说明未来按"各构件权重 + 病害扣分"动态计算 |
| C7 | 0.3m 是净空余量还是侵限深度 | **0.3m 是安全余量（Clearance Margin）**。图例：🟢余量 >0.3m；🟡余量不足 0~0.3m；🔴侵限（侵限深度 >0m，即余量为负）。着色与弹窗前先统一符号方向 |
| C8 | 报告三维截图来源 | **前端截屏**：`viewer.canvas.toDataURL('image/jpeg', 0.8)`，Base64 随请求发后端，后端校验并嵌入 HTML；Cesium 不做服务端渲染 |

## 3. 优先级分组

**P0（界面与流程）**：A1–A11。
**P1（数据与算法接入）**：A12 权重评分、A13 生命周期曲线、A14 全量导出审计、A15 批量流水线、C1 等级持久化。
**P2（交付增强）**：PDF 渲染引擎、报告三维截图自动生成、逐点热力图真实着色、审计链并发写完善。

## 4. 占位标注约定（强制）

- `示例数据 · 算法待接入`
- `示例阈值 · 待规范库确认`
- 条款号统一 `第 5.x 条（具体条款以正式规范为准）`
- 侵限色阶 `示例阈值 · 可被甲方规范覆盖`（安全余量口径）
- 含示例标注的报告页眉保留警示条，不得用于验收。
