# T-11 异步任务框架

| 项 | 内容 |
| --- | --- |
| 阶段 | P3 |

## 1. 目标

让推理、转换、几何分析、缩略图都走同一套可观测的异步模型，而不是各写一套线程。

## 2. 输入

- async_task 表
- Redis 队列
- V1.2 §9.5 异步任务模型

## 3. 改动范围

- 允许：backend/app/workers/**、modules/task/**
- 禁止：业务模块自建线程池

超出上述范围即视为越权改动，即使代码正确也退回。

## 4. 实现要点

- 状态 QUEUED/RUNNING/SUCCEEDED/FAILED/RETRYING/CANCELLED/TIMEOUT，写入即不可跳变
- `idem_key` 唯一索引，重复提交返回既有任务 ID（202）
- 重试指数退避 5/15/45 s，最多 3 次；副作用必须幂等
- `timeout_sec` 到点由看门狗置 TIMEOUT，并释放锁

## 5. DoD（可验证的完成定义）

- 同一 idem_key 提交 3 次只产生 1 个任务
- 消费者崩溃后任务回到 QUEUED 而非永久 RUNNING
- 超时任务可取消且资源释放
- 任务表按 status 建索引，查询 < 100 ms

## 6. 验收用例

| # | 输入 | 操作 | 期望结果 |
| --- | --- | --- | --- |
| 1 | 相同 idem_key 连点提交 | POST /inference/tasks ×3 | 均返回 202 且 taskId 相同 |
| 2 | 任务执行中进程被杀 | kill worker | 60 s 后任务回 QUEUED，attempt 不变 |
| 3 | timeout_sec=30 的任务跑 40 s | 等待 | 置 TIMEOUT，结果引用为空 |

## 7. 依赖与顺序

T-02 之后，T-09/T-10/T-17/T-20 依赖它。

## 8. 常见坑

- 不要在事务提交前入队
- 不要让重试重复写结果表
- 不要把大结果放 async_task 里，存 result_ref
