# T-22 离线 Outbox 与同步

| 项 | 内容 |
| --- | --- |
| 阶段 | P6 |
| 依赖前置 | T-08 |
| 产出 | 客户端 Outbox、client_seq 去重、增量拉取、冲突提示、PMS 增量同步与对账 |
| 验收门 | 断网 30 分钟后恢复可完整同步；重复提交不产生重复单 |
| 预估工作量 | 5 人日 / 3 卡 |
| 人工主导 | 是（人工主导：PMS 字段映射需厂商确认） |
| 外部阻塞 | 阻塞于 C-17（PMS 接口协议与字段映射） |

## 1. 目标

让弱网与断网不产生脏数据，冲突时以服务端为准并明确提示。

## 2. 输入

- API-20、API-16 至 API-18
- sync_log
- `updated_since` + `X-Sync-Token`

## 3. 改动范围

- 允许：frontend/src/offline/**、backend/app/modules/sync/**
- 禁止：改工单状态机的迁移语义

超出上述范围即视为越权改动，即使代码正确也退回。

## 4. 实现要点

- `client_seq` + `order_id` 唯一去重，服务端按此幂等
- 增量拉取必须包含软删除，前端据此移除本地记录
- 冲突（version 落后）返回 409，前端展示“已被他人修改”并刷新
- PMS 同步失败进 sync_log 并告警，不阻塞本地闭环

## 5. DoD（可验证的完成定义）

- 断网建单后排队的 3 条记录恢复后全部成功且不重复
- 增量拉取遗漏 0 条
- 版本冲突有明确提示
- PMS 不可用时本地流程照常闭环

## 6. 验收用例

| # | 输入 | 操作 | 期望结果 |
| --- | --- | --- | --- |
| 1 | 断网提交两次同一工单 | 恢复网络 | 服务端只建 1 单，第二次返回首次结果 |
| 2 | 本地 version=2，服务端已到 3 | 提交流转 | 409 并提示刷新，不覆盖 |
| 3 | PMS 接口超时 | 同步 | sync_log 记失败，重试，不影响工单 |

## 7. 依赖与顺序

T-08 之后；C-17 未定时只能做本地离线部分，PMS 对接留 TODO。

## 8. 常见坑

- 不要用时间戳当唯一去重依据
- 不要在客户端缓存他人数据
- 不要静默覆盖服务端变更
